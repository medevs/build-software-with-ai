    What the app knows right now

    State & Storage

    "It forgot my cart" is one of the most common software complaints there is. Almost always, it traces back to the same mix-up: something the app should have written down permanently was only ever held in its head.

    "State" is what the app currently knows

    State is a word for everything an app currently knows about what's going on: are you logged in? What's in your cart? Which tab is open? Every one of those facts is a small piece of state, and the app has to keep it somewhere. The whole question this lesson answers is: somewhere, but where, exactly — because different somewheres behave very differently.

    Four places state can live

    Why mixing these up causes real bugs

    "It forgot my cart" is usually one specific mistake: the cart was kept only in memory or a session, when the user expected database-level permanence. Add an item, close the app before checking out, come back tomorrow — and if the cart lived only in short-term state, it's gone, even though nothing "went wrong" from the computer's point of view. It did exactly what it was told; it just wasn't told to remember that far.

    Getting this right isn't a technical detail — it's a judgment call about user expectations, which is something you can absolutely weigh in on without writing a line of code.

    A quick look ahead: caching

    One more term you'll hear: caching, which means keeping a fast, temporary copy of information that's really stored somewhere else (usually the database), so the app doesn't have to fetch it the slow way every single time. It's a close cousin of the "where does state live" question — but it comes with its own tricky failure mode (showing you stale, out-of-date information), so it gets a full lesson of its own later in the course.

    Why this matters for you When you hit a bug where the app "forgets" something, the first useful question isn't "what's broken" — it's "where was this supposed to be stored, and was it actually stored there?" That single question resolves a surprising share of real bugs.
    Red flags to catch
    • Something the user would expect to survive closing the app — a cart, a draft, a setting — is only ever kept in memory or a session.
    • Sensitive information (like a full card number) is kept around in storage longer than it needs to be.
    • Nobody can tell you, for a given piece of data, which of the four places it actually lives.
    Ask your AI
    • "Where exactly is [this specific piece of data] stored — database, session, file, or just memory?"
    • "If the user closes the app right now, what will they lose?"
    • "Is anything here being saved permanently that should really just be temporary?"

    The one thing to remember

    State is what the app knows right now, and it can live in the database, a session, a file, or memory — mixing those up is exactly how "it forgot my cart" bugs happen. Matching the storage to how permanent the user expects it to be is the whole game.
